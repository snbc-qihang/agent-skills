# 导出 API Controller 边界经验

适用场景：导出接口需求调整，尤其是“导出接口不再接受筛选条件”“权限由服务端生成”。

## 核心规则

1. Controller 只做接口编排
   - 接收请求、返回响应。
   - 调用 facade/service。
   - 不堆积权限计算、快照构建、租户类型判断、集合去重等 private 工具方法。

2. 导出范围只改导出
   - 如果用户说“只处理导出相关功能”，不要修改分页查询路径、分页查询时间处理、普通列表查询注释。
   - 导出接口路径规范不能外推到非导出接口。

3. 删除筛选入参要形成接口契约
   - 导出创建接口方法参数为 0 或不含查询 DTO。
   - 不从前端取 orderId/phone/tenantIds/cityIds/payStartTime/payEndTime。
   - 权限范围由 token 用户/租户 + 现有权限服务生成售货机快照。

4. 注释要解释业务变化
   - 中文说明“不接收前端筛选条件”。
   - 写清权限来源、查询范围、返回异步任务信息。
   - 商品维度字段删减要在接口/DTO 注释中体现。

## 推荐分层

- Controller：导出接口、任务查询、下载接口。
- Facade：当前 token 用户/租户校验，创建任务、查询、下载的编排。
- SnapshotBuilder：租户类型判断、调用权限服务、生成导出查询快照。
- Handler：按快照 count/queryPage/buildFileName。
- Mapper/XML：只按导出快照字段查询宽表。

## 常见坑

- 为了消除 Controller private 方法，误把非导出分页查询也改了。
- 将“导出接口路径使用驼峰”外推到分页查询路径。
- 商品维度明明确认不导出 phone/payChannel，却通过 join 主表补回旧列。
- 快照构建时仍携带前端筛选字段，导致“删除入参”只是表面变化。
