# Self-improvement Evidence

Read this reference before changing live Engineering Assistant skills during self-healing, sleep, evolution, compression, or capability optimization.

## Darwin evidence

Record the target skill, trigger, four-layer maturity before/after, missing assets, bounded upgrade plan, validation result, and gate impact. Evaluate the live effect, not only wording or line count. Preserve an edit only when deterministic checks and realistic regression behavior do not decline.

## SkillOpt-Sleep evidence

Record:

- action: `status`, `dry-run`, `run`, or `adopt`
- project path, transcript source, and backend
- `n_sessions`, `n_tasks`, baseline score, candidate score, `gate_action`, and `accepted`
- `staging_dir` and whether `report.md` was read

Do not adopt when `accepted=false`, no staging directory exists, or held-out score does not improve. A staged proposal requires reading `report.md` and explicit user approval before `adopt`.

If a first run against the target path returns no sessions or tasks while the user asked to use current/past Codex context, rerun read-only gathering with `--source codex --scope all` and record both attempts.

Use `SKILLOPT_SLEEP_CONTEXT_FALLBACK_NOT_RUN`, `SKILLOPT_SLEEP_GATE_NOT_RECORDED`, or `SKILLOPT_SLEEP_ADOPT_WITHOUT_APPROVAL` only for the corresponding missing evidence or unauthorized adoption.

## Ratchet decision

User-authorized direct edits may proceed independently of a Sleep proposal, but must still record Darwin evidence, the Sleep result, a rollback path, and post-edit deterministic plus realistic regression evidence. Sleep output is evidence, not a competing controller; Engineering Assistant remains the sole gate owner.
