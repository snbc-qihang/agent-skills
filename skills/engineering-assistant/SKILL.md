# 工程助手

将请求转换为结构化 `RouteIntent`，再交给运行时路由器。只加载选中的公开 skill、flow 节点和被引用的 policy。

## 操作流程

1. 在询问用户前，先调查可能改变路由的事实。
2. 单个原语能够完成任务时只选一个原语；只有存在依赖关系的多步骤任务才选择 flow。
3. 明确记录范围、风险信号、外部动作和置信度。
4. 遇到 `ask`、`confirm` 或 `block` 时立即停止，不得把它们解释为继续执行的许可。
5. 对持久化 flow，以运行时状态作为进度的唯一事实源。
6. 阶段或切片完成后，在平台支持委派时默认发起子 Agent 自动评审：至少分别检查原始需求/架构契约与代码质量/安全回归，并由主 Agent 闭环可修复问题。
7. 只有自动评审发现必须由用户决定的产品取舍、风险授权、不可逆动作或无法消除的证据冲突时，才暂停并请求人工判断。
8. 把用户给出的工具、查询、文件和只读预算原样传递给选中 skill；预算不足时返回未知项或阻断，不得通过额外扫描“补全”。

当前平台暴露 `engineering_assistant_route` 时，先调用一次该工具获得 flow、skill 和 policy，再加载选中 skill；不得扫描插件目录猜测路由、工作流或 validator。阶段状态审计、自动评审通过条件、blocker 和门禁判断属于 `code-review`，不是通用 `repo-context`。只有用户明确指向历史上下文，或当前仓库事实无法解释状态时，才加载 memory/rollout。

用户未给预算的只读阶段审计，默认上限是：一次 Runtime 路由、一次代码索引查询、八个证据文件和六个 shell 命令。路由结果已经给出的 flow、skill、policy 直接使用，不得再读取 catalog 验证。证据预算必须优先分配给用户点名的阶段结果、自测、代码评审和运行证据；索引查询还必须覆盖当前 diff 中的鉴权、秘密、持久化和外部动作高风险路径。发现足以阻断阶段通过的事实后，只补齐用户明确要求的其他风险轴，不得继续枚举整个产品合同。

只有工作超过一次会话时才读取 [references/wayfinding.md](references/wayfinding.md)。只有路由包含写入、发布、生产或外部动作时才读取 [references/authorization.md](references/authorization.md)。

只有在路由已经说明且未加载多余 skill 或参考资料时才可完成。
