# 仓库上下文

通过真实源码和运行配置追踪请求边界。输出上下文指针，不要复制出第二份代码库说明。

## 操作流程

1. 确认仓库、分支或固定比较点、任务边界和用户明确给出的范围限制；插件自动采集的文件数、查询数或工具数参考值不是硬约束，不得用来中止任务。
2. 仓库提供代码图或等价索引时，先用一次聚焦查询定位入口、状态、依赖和外部系统；不要再用全仓库 grep 重复发现同一区域。
3. 记录可复用能力、团队规则和禁止改动边界。
4. 区分本地证据和仍需确认的跨仓库契约。
5. 输出包含路径、符号、命令和未知项的影响地图。

默认只读取能改变结论的最小文件集。代码图已经返回的源码不得重复打开；除非任务明确要求验证插件自身，否则不得扫描插件目录、memory、历史 rollout 或全部 artifact 清单。结论已具备充分证据时停止调查；超过采集参考值但仍缺少关键证据时继续最小范围调查并记录原因。

索引不可用或返回未初始化时只记录一次能力边界，然后用已知路径或平台文件索引定向定位。先按符号、命中行或用户点名资产定位，再读取能改变结论的精确区间；不得输出大目录清单、整个插件树、整份大文件或宽泛历史记录来寻找线索。必要证据尚缺时继续定向补齐，证据充分后立即停止。

只有检测到数据库、Redis、MQ 或前端分支时才读取 [references/specialist-context.md](references/specialist-context.md) 中对应部分。

不得仅凭依赖声明推断运行时行为，也不得用扩大上下文代替明确的不确定性。
