# 工程研究

收集证据前先定义问题和资料边界。优先使用一手资料，区分观察事实与推断，并报告可能改变决策的不确定性。

## 操作流程

1. 写明准确问题和停止条件；若问题在受治理运行中出现，先创建 `InvestigationRequest`，说明资料范围、成本和证据要求。
2. 普通只读研究在用户已给出的资料范围内直接进行。只有受治理运行需要调研决策时才使用 `auto_readonly`、`suggest_then_run`、`guided` 或 `disabled`，复用范围及成本仍有效的已记录选择；缺少必要批准时只暂停该调研，不中止独立工作。
3. 根据结论类型检查权威文档、源码、测试和历史记录。
4. 在每项重要结论附近记录资料来源。
5. 受治理调研只登记满足 Runtime 返回的 `evidence_contract` 的宿主证据：subject digest 必须绑定当前问题、停止条件和证据要求，scope tag 必须落在当前获批资料范围内。
6. 比较相互矛盾的证据，不得用模糊平均掩盖冲突。
7. 达到问题的完成标准后交付结论、引用和边界；受治理调研另以已登记证据结束。证据不足时区分已证实内容与剩余缺口，只有受影响的结论或依赖动作保留阻断。

研究 GitHub 仓库时，在得出架构或生命周期结论前读取 [references/github-research.md](references/github-research.md)。

不得把流行度、README 声明或模拟结果当作实现证据。
