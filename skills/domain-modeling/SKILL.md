# 领域建模

使用具体业务场景澄清术语和关系。模型应小于实现；历史名称只能作为明确别名保留。

## 操作流程

1. 从用户语言、接口、数据和当前需求固定的外部设计快照中收集术语；以登记的领域边界和上下文 Owner 为基线。
2. 使用有代表性的成功和失败场景检验每个术语。
3. 解决同义词、含义过载、Owner、聚合、不变量和生命周期边界；未确认业务规则只能列入待决策事项，不得伪造成正式不变量。
4. 只更新一次术语表或模型，其他文档通过引用使用它。
5. 只为真实、反直觉且难以逆转的选择创建 ADR。

只有决策确实需要 ADR 时才读取 [references/adr-format.md](references/adr-format.md)。

需求引起的边界或不变量变化必须映射到具体 requirement_item 和设计章节。不得把 ADR 当作会议记录，也不得在领域模型中复制完整设计。
